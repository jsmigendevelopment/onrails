# Changelog

All notable changes to the kit are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The kit's version is the one at the bottom of `AGENTS.md`. The CLI on npm carries the same version.

## [Unreleased]

### Added

- **Each web-pack add-on says whether it fits an app whose backend is Go (#540).** Every `ADDON.md` table has a "With a Go backend" row, and `stacks/tanstack-start-addons/README.md` lists them in one table: `analytics` and `sentry` (the web app's browser and Worker) fit; `stripe`, `jobs`, `r2-uploads`, `email-resend` and `database-supabase` are for a TypeScript backend on Workers, and on a Go backend the need goes in the Go service. The `saas`, `marketplace` and `api-service` presets' add-on lines say the same. Words only: `npx onrails add` still copies any add-on. `cli/test/addon-go-backend.test.mjs` guards it.
- **Secrets and environments for a Go service (#536).** `guide/environments.md` gives each example that names `pnpm deploy:test`, `wrangler` or `lib/env.ts` a Go form beside it (Cloud Run, Secret Manager, one `Config` struct, every variable on every deploy). The `secrets` skill's pack-without-the-script lines, `setup/README.md`, `idea`, `join`, `coordinate` and the stack template name `gcloud` and `push-secrets.mjs --cloud-run`, checked by name, never a value. `clerk.md` has a Go backend paragraph, and two new walkthroughs, `cloud-run.md` and `neon.md`, have connect blocks that fill only names no web pack lists, so `pnpm connect` in a web app is unchanged.
- **A code style for a Go backend, and the two TypeScript-only rules in `AGENTS.md` name their Go equivalent (#533).** The new `guide/code-style-go.md` is the Go version of the `code-style.md` rules that name a TypeScript tool (3, 4, 14 and 15) and of 5, 11 and 12, numbered the same. Each has the rule, a short Go example and the tool that keeps it: no `any` or `interface{}` in an exported signature, a `//nolint` only with a linter name, a reason and an issue number, `gofmt` and three import blocks, no `init()` that does work, no `util` package, errors wrapped with `%w` and never ignored, no `fmt.Println`, and money, time and access through their one package. It names only the tools of the Go toolchain dossier (golangci-lint with depguard, funlen and nolintlint, revive's `file-length-limit`, go-arch-lint, `internal/` folders) and says plainly where no tool checks a rule yet. `AGENTS.md`'s escape-hatch rule gains "or the stack's equivalent (`//nolint` in Go)" and its barrel rule "or the stack's equivalent (in Go, a package that only re-exports)"; nothing else in it changes. `guide/README.md` and `code-style.md` link to the guide. Decision 533-1 (AI pick, not reviewed).
- **`build`, `pr-review` and `web-security` read the same for a Go backend as for a TypeScript one (#534).** The errors, logs, API, OpenAPI, money, time, database, env and text lines of `build`'s App rules and `pr-review`'s step 6 keep their rules and no longer name `lib/*.ts`, Zod, Drizzle, `AppError` or a server function: each points at rule N of `app-conventions.md` or `app-conventions-go.md`, picked by `docs/stack.md`'s Backend row. `build`'s code rules point at `code-style.md` or `code-style-go.md`. `web-security` rule 4 names `json.Decoder.DisallowUnknownFields` beside `z.strictObject`, and an "On a Go API" section gives the body cap, server timeouts, rate limit and security headers for Cloud Run, each with its checked date and source. The Go guide is copied into `build/references`, with a row in its References table.
- **Agents ask once whether you type or dictate, and read voice to text by sound (#457).** `/idea`, `/join` and `npx onrails profile init` ask "Do you mostly type, or use voice to text?" once and save `[me] input` (typing, voice or both) in your personal profile; it is never copied into a project. With voice or both, `AGENTS.md` points to `ask`'s new `references/voice.md`: read by sound, never correct the wording, confirm in one line only in a risky spot (money, deleting, deploying), and on Full take the likely reading as an AI pick. `ask/scripts/voice.mjs` prints the setting and your glossary of confirmed mishearings (`~/.onrails/glossary.toml`, the kit's own names built in) and adds a line when you confirm one. The opt-in eval `voice-reading` covers "use 10 stack start".
- **Go modules, pinned and checked like npm packages, and the Dependabot gate that merges their bumps (#531).** `dependabot-bump.mjs` (through `own-branch.mjs`) now passes a Dependabot bump that changes only the versions of existing `require` lines in a `go.mod` and adds only `go.sum` lines of the form `<module> <version> h1:<hash>` or `<module> <version>/go.mod h1:<hash>`, with the same exit codes as an npm bump. It reads `go.mod` strictly at the merge base and the head and refuses, naming the line: a new or changed `replace`, `exclude`, `retract`, `godebug`, `tool` or `ignore`; a changed `module`, `go` or `toolchain` line; a new, removed or renamed module path; a version that isn't a full `vMAJOR.MINOR.PATCH`; any other `go.sum` line; a `go.mod` line it can't read; and any file but `go.mod` and `go.sum`. The `dependencies` skill gets the Go command beside every npm one (`go list -m -versions`, `go mod download -json`, `go get <module>@<tag>`, `go mod verify`, `go mod tidy -diff`, `go build -mod=readonly`, `go-licenses`, `govulncheck`) with no npm rule changed. The Go code is in the new `dependabot-go.mjs` (decision 531-1, AI pick, not reviewed).
- **A usage reading's window and reset time are recorded, so the weekly report can tell a reset from a cheap run (#431).** The `job` record takes the optional `usage_window_before`, `usage_window_after` (such as `seven_day`) and `usage_resets_before`, `usage_resets_after` (UTC, as `toISOString` writes it), each held as tightly as the other fields and only with its own reading; `build`, `pr-review`, `pr-security` and `qa` pass them where the tool shows them. `insights-week.mjs` gives a run's usage, and its pull request's, as `unknown` when a reset time falls inside the run or its two readings name different windows. An escalation row beside a build with an unknown model or effort says `unknown` for "Fixed it", not `yes`.
- **The agent-file guard sees a Go app's check code and tests (#532).** `agent-files.mjs` now treats `.golangci.{yml,yaml,toml,json}`, `.go-arch-lint.{yml,yaml}`, `Makefile`, `GNUmakefile`, `Taskfile.{yml,yaml}` (and `.dist`), `justfile`, `sqlc.{yaml,yml,json}`, `orval.config.*` and `tools/*.mod` as check code at any depth, and a removed or renamed-away `_test.go` file or `testdata/` file as a deleted test; adding or editing one stays unprotected, as for `.test.ts`. `automation/references/full.md` lists the same names, and the carry logic and every existing case are untouched. `.go-arch-lint.*` and `tools/*.mod` come from the Go toolchain dossier (decision 532-1, AI pick, not reviewed).
- **Preflight and doctor look at Go when the repo has a `go.mod` (#538).** Preflight adds two rows after Node and the package manager: the Go toolchain (`go version` against `go.mod`'s `go` line) and the Go module proxy (one module's version list through `GOPROXY`, honouring the session's proxy). A blocked proxy gets its own ladder: a project-local `GOMODCACHE` and a mirror in `GOPROXY`, then the one batched message, and "installs are blocked" covers both rows. Go runs with `GOTOOLCHAIN=local` from an empty folder outside the repo, so it never fetches a toolchain, and the fingerprint moves with `go.mod`. `doctor` says whether `go` is found and new enough, with the install fix, and never runs a `go` the project ships. A folder with no `go.mod` prints the same table as before (decision 538-1).
- **The app conventions for a Go backend (#348).** [`guide/app-conventions-go.md`](guide/app-conventions-go.md) is the Go version of the server-side sections of `guide/app-conventions.md` (5, 8, 10 to 16 and 18), numbered the same: one error envelope with a request ID, one `log/slog` JSON logger, `Money` in integer minor units, instants as UTC `time.Time`, events only through `track()`, access only through `check(user, action, object)`, one typed config read once, and the API under `/api/v1`. `guide/README.md` and `app-conventions.md` link to it, and `cli/test/go-conventions-guide.test.mjs` checks the sections, the length and the links. A guide only: no pack code (decision 348-1, AI pick, not reviewed).
- **Each pull request's counted size is recorded, so the weekly report can bucket it (#427).** `pr-size.mjs --record issue=<n> model=<m> effort=<e> tool=<t>` writes the `job=size-check` record itself, pass or fail, with the new optional `lines` field (the counted lines, held to the same strict format) plus the pull request and head sha from its own count; `coordinate` step 6.1.1 uses it in place of the hand-run send-back command. `insights-week.mjs` fills the under 500, 500 to 999 and 1,000 or more buckets from each pull request's last size check in the week (pull requests, sent back, rate), and a pull request with no size record stays under `unknown`. `has-records` and `carry` don't take a size check for the review job. Decision 427-1.
- **Which model did which job (#129).** `insights.mjs line job` now ends with a run line people read on GitHub: job, model, effort, time from `started=`, and the commit. `build` ends its pull request body with one and its commits with `Agent-Model:` and `Agent-Effort:` trailers; `pr-review`, `pr-security` and `qa` pass `started=`. A new optional `model_from` field says why a model or effort is `unknown`. `validate` refuses a control character in `job`, `model`, `effort` and `model_from`, so the run line stays one line. `npx onrails runs --pr <n>` (or `--issue <n>`, `--day <yyyy-mm-dd>`) prints the chain from the records, oldest first, and `--brief` gives `/back` one line per merged pull request (decision 129-1).
- **Every stop, wait or ask writes a record naming the rule that caused it (#334).** `notify.mjs` takes `--rule <path>:<line>` and `--always-stop`, and after it decides the ping it writes an `ask` insights record with the rule (`missing` without one, `hook:<event>` from a hook), `rule_ok`, the level, the issue, the title and `full_should_prevent`. Its JSON names the record's path. No writer in the repo, or a failed write, never changes the ping. `insights.mjs write ask answered=<file>` writes the answer record with the minutes waited. `ask` says to pass `--rule` and to write the answered record. `validate` refuses a control character in an ask's rule or title (decision 334-1).
- **A research dossier on the Go pack's toolchain (#342):** [`research/go-api-toolchain.md`](research/go-api-toolchain.md), with its sources, claims, scratch-app experiments and a fact-check in a fresh session. Picks for the lint and module boundary (golangci-lint, go-arch-lint, Go's `internal/` folders), the six check commands as `package.json` scripts with Playwright for `test:e2e`, a code-first contract (huma, orval, and a regenerate-and-compare step in `typecheck`) and the ServeMux router, each with a pinned version and a re-check command. Decision 342-1, AI pick, not reviewed. Research only: no pack code.
- **Local mode's merge step checks the records too (#415).** `insights.mjs has-records --issue <n> --sha <sha>` is `--pr`'s form for local mode, which has no pull request: it matches the records' `issue` and exact sha, and exits 1 naming each missing kind. `local-mode.md` step 5 runs it before `git merge --no-ff` and merges only on exit 0, and step 4 says how the `check` record is written (decision 415-1).
- **`push-secrets --cloud-run` puts a Go service's values on Google Cloud Run (#537).** Each secret goes to Secret Manager (`gcloud secrets create`, else `versions add`, the value on stdin) and each plain variable to the service's environment (`gcloud run services update` with a temp `--flags-file`), so no value is ever an argument or in the output; `--dry-run` lists names and destinations only, and a failure exits 1 and ends on "Stored nowhere" or "Not stored everywhere", as for `--wrangler`. In a repo with a `go.mod`, `setup-github`'s closing line and push-secrets' own messages name `--cloud-run` instead of only Cloudflare; without one they are unchanged The `--flags-file` mapping form parsed under real gcloud but has not yet run against a live service. A flag written `--name=value` now exits 1 before any call (decision 537-1, AI pick, not reviewed).

### Fixed

- **The monorepo-expo pack says `eas env:set`, not the deprecated `eas env:create`,** in its README and `.env.example`, matching eas-cli 27.11.0, where `env:set` creates or updates a variable. The Expo provider file's trap note now says why (#15).
- **Keys from `clerk env pull` work with no rename (#13).** The TanStack Start pack reads the publishable key as `VITE_CLERK_PUBLISHABLE_KEY`, the name Clerk's TanStack Start quickstart uses and its CLI writes; the env schema, `.env.example`, `wrangler.jsonc`, the Clerk connect block and walkthrough, the stack skills and the monorepo pack say so, and the rename steps are gone. The old `CLERK_PUBLISHABLE_KEY` still works, with one `env_name_deprecated` warning in the Worker log; the new name wins when both are set.
- **Clerk tokens are checked against the app's own origins** (`authorizedParties`) in the TanStack Start pack, for the session cookie and `/api/v1` bearer tokens. The list comes from `SITE_URL`, localhost and the test Worker's previews, so there is no new setup step; `CLERK_AUTHORIZED_PARTIES` adds more. A token for another site, or with no `azp`, gets the same 401 as no token, and production with Clerk keys but no origin refuses to start. Native apps, whose tokens have no `azp`, opt in with `CLERK_ALLOW_NATIVE_TOKENS` (bearer on `/api/v1` only); the monorepo-expo pack turns it on. The refusal reason no longer reaches the page or the response headers. The `Authorization` header is parsed exactly as Clerk does (`bearer x` no longer counts), and on `/api/v1` the cookie never reaches Clerk (#12).
- **A look-alike path no longer slips past the path guards** in the TanStack Start pack. The router matched case-insensitively and decoded escaped letters, so `/API/v1/notes` or `/%61pi/v1/notes` reached the API without the body cap, the rate limit or the cookie removal, and `/NOTES` skipped the Worker's Access check. The router is now case-sensitive, and the request guards answer with a plain 404, server functions included, any path Start would resolve to another one: an empty segment (`/api//v1`), an escaped control character or trailing space (`/notes%20`), or anything Start's own `getNormalizedURL` decodes (`/%61pi`, `/%5FserverFn`). Every guard then compares the path Start routes (`canonicalPath`, #18).
- **Three notes from the path-guard security review (#65)** in the TanStack Start pack. A lowercase escape of a non-ASCII character (`/notes/caf%c3%a9`, sent by some API clients) routes like the uppercase one instead of a 404, and every guard compares the path Start routes; escaped unreserved and control characters and a trailing `%20` are still refused. `//x` (Start's 308) and an empty server function ID (`/_serverFn/`, Start's bare 500) are answered before Start's handler by `beforeStart` in a new Worker entry, `src/server.ts` (`main` in `wrangler.jsonc`), with the guards' plain 404 and the security headers; the `sentry` and `jobs` add-ons' entries keep that call. An unknown server function ID gets the `internal` envelope with the security headers, not Start's `Server function info not found` 500.
- **A native token also needs the app's own claim** in the TanStack Start pack. With `CLERK_ALLOW_NATIVE_TOKENS=true`, a bearer token with no `azp` got through from any app on the same Clerk instance. It now needs an `app` claim equal to the new `CLERK_NATIVE_APP_CLAIM`, which the person adds to the instance's session token claims (a "Setup step for you" in the `secrets` skill's Clerk file); no claim, a wrong or non-string one, or the flag without the variable is the uniform 401. Clerk's custom claims are per instance, so this can't tell two apps on one instance apart: one Clerk application per product stays the rule. The monorepo-expo pack sets the variable (#19).
- **Tests for the Clerk guards that nothing failed without** in the TanStack Start pack. An e2e check that a valid cookie plus a bare or inexact bearer token is a 401 and that Clerk never saw the cookie (`x-clerk-auth-status`), so unwiring `requestForClerk` fails it; a unit test that the `@clerk/backend` dev dependency is the version `@clerk/tanstack-react-start` resolves, so the header parity test can't go stale. On `/api/v1`, Clerk's own query parameters no longer reach Clerk: a junk `__clerk_handshake` made a development instance throw (a 500), and `__clerk_redirect_url` (an open redirect), `__clerk_db_jwt` and `__clerk_synced` started a redirect. `requestForClerk` drops every `__clerk*` parameter there, and any redirect Clerk still answers with on the API is the uniform 401 (#20).
- **A crafted link can no longer send a tester's Clerk dev session to another site (#66)** in the TanStack Start pack. On a development instance, `@clerk/backend` answered `/notes?__clerk_redirect_url=https://evil.example` with a 307 to that site carrying the dev browser token (`__clerk_db_jwt`). The request guards now answer a `__clerk_redirect_url` or `__clerk_satellite_url` that isn't on one of the authorized parties with a 400 on every path (the API already dropped them, so it stays the 401), Clerk no longer sees the client's `X-Forwarded-*` or `Forwarded` headers, which put a spoofed host in its handshake URLs, and any redirect Clerk itself throws outside the parties and its Frontend API, or to the Frontend API with a `redirect_url` off the parties, gets the same 400. The development sign-in, handshake and satellite sync flow is unchanged and tested; production instances never take that path.
- `.clerk/` (Clerk claim files and temporary keys) is git-ignored in both packs, and CI fails if anything under it is committed.
- **The first pull request can merge now.** `setup-cloudflare` deploys the test Worker once, as the Coming soon page, so previews have a Worker to upload to. `--no-first-deploy` skips it. If the test Worker is missing, the `preview` job fails and names the fix (#3).
