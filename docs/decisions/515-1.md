# Decision 515-1

- **Date:** 2026-11-28
- **Decision:** How the add-on lint test reads touched files and stray lint (#515, from the review of #508). (1) `isNewFile` counts a backticked path only when its first folder is a plain name or a dot folder (`.github/x.yml`), so a host path such as `example.com/docs/a.html` is not a file the step makes. (2) A path the pack's lint and format skip is never touched, whatever the prose says: `.prettierignore` is read as the pack reads it (comments dropped, a line with a `/` starts at the pack's root, a line without one matches at any depth), so `node_modules/...` and `docs/stack.md` (`/docs`) are not counted. (3) `STRAY` names each way to run ESLint or Prettier: a package manager with flags and `exec`, `run`, `dlx` or `x` (`pnpm -s exec eslint`), `npx`, `bunx` and `pnpx`, and the binary by any path (`./node_modules/.bin/eslint`). `pnpm format`, `pnpm fix` and `pnpm lint --fix` also take a flag after the package manager and `npm`, `yarn` or `bun` in its place. (4) The AC-435-1 test's child result goes through `childResult`, which fails with the add-on, the shape, the exit code and stderr when the child printed nothing; what AC-435-1 asserts is unchanged. (5) On the seven add-ons' Apply sections the touched list is the same before and after (shown in the pull request).
- **Options considered:** For (2): skip only `node_modules/` (leaves `docs/stack.md`, which the issue names); only count a path whose line has a making verb such as "Create" or "Add" (the add-ons word these steps many ways, so a real file could be missed, which is the worse error for a guard). For (3): list the three forms the issue names only (the next form, `pnpm dlx` or `bun x`, would slip through again).
- **Why:** The guards must catch more, never less. Dropping a path the lint skips cannot hide a file it would check, and the before and after lists show no path a real step makes was lost.
